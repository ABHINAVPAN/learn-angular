 ✅ New values require creating a new object
 ✅ Thread-safe by nature
 ✅ Safe to share across multiple threads

Difference between map() and flatMap()?

MAP() vs FLATMAP() IN JAVA 8

1. map()

Definition:
- map() is used for one-to-one transformation.
- Each input element produces exactly one output element.
- It transforms data but does not flatten it.

Syntax:

Stream<R> map(Function<T, R> mapper)

Example:

List<String> names =
Arrays.asList("java", "spring", "angular");

List<String> result = names.stream()
                           .map(String::toUpperCase)
                           .collect(Collectors.toList());

Output:

[JAVA, SPRING, ANGULAR]

Flow:

java    -> JAVA
spring  -> SPRING
angular -> ANGULAR

One Input -> One Output


--------------------------------------------------

2. flatMap()

Definition:
- flatMap() is used when each element contains multiple elements.
- It transforms and flattens nested structures.
- Converts multiple streams into a single stream.

Syntax:

Stream<R> flatMap(
    Function<T, Stream<R>> mapper
)

Example:

List<List<String>> list = Arrays.asList(
    Arrays.asList("Java", "Spring"),
    Arrays.asList("Angular", "React"),
    Arrays.asList("SQL", "MongoDB")
);

List<String> result = list.stream()
                          .flatMap(x -> x.stream())
                          .collect(Collectors.toList());

Output:

[Java, Spring, Angular, React, SQL, MongoDB]

Flow:

Input:

[
 [Java, Spring],
 [Angular, React],
 [SQL, MongoDB]
]

After flatMap:

Java
Spring
Angular
React
SQL
MongoDB

Nested Lists -> Single Stream


--------------------------------------------------

3. map() vs flatMap()

Using map():

List<String> words =
Arrays.asList("Java", "Spring");

List<String[]> result =
words.stream()
     .map(word -> word.split(""))
     .collect(Collectors.toList());

Output:

[
 [J,a,v,a],
 [S,p,r,i,n,g]
]

Result remains nested.


Using flatMap():

List<String> result =
words.stream()
     .flatMap(word ->
         Arrays.stream(word.split("")))
     .collect(Collectors.toList());

Output:

[J, a, v, a, S, p, r, i, n, g]

Result becomes a single flattened list.


--------------------------------------------------

KEY DIFFERENCES

map()
------
- One-to-One Transformation
- Returns Stream<R>
- Does not flatten data
- Used for simple conversions
- Maintains original structure

flatMap()
----------
- One-to-Many Transformation
- Returns Flattened Stream<R>
- Flattens nested data
- Used for nested collections
- Removes one level of nesting


--------------------------------------------------

RETURN TYPES

map():

Stream<String>
      |
      V
map(String::length)
      |
      V
Stream<Integer>


flatMap():

Stream<List<String>>
          |
          V
       flatMap()
          |
          V
Stream<String>


--------------------------------------------------

COMMON USE CASES OF flatMap()

1. List<List<Integer>>

2. Department -> List<Employee>

3. Stream<String[]>

4. Optional<User>

5. Nested Collections


--------------------------------------------------

INTERVIEW ANSWER

map() is used for one-to-one transformation where each input element is converted into exactly one output element.

flatMap() is used when each element itself contains multiple values. It converts each element into a stream and
then flattens all streams into one single stream.

In simple words:

map()     = Transform

flatMap() = Transform + Flatten


MEMORY TRICK

map()     -> One Input  -> One Output

flatMap() -> One Input  -> Multiple Outputs
             + Flatten Everything

DIFFERENCE BETWEEN THREAD AND RUNNABLE
=========================================

1. THREAD

- Thread is a class present in java.lang package.
- Used to create and manage a thread.
- Contains methods like start(), sleep(), join(), etc.
- A class must extend Thread to create a thread.

Example:

class MyThread extends Thread {

    @Override
    public void run() {
        System.out.println("Thread Running");
    }
}

public class Main {
    public static void main(String[] args) {

        MyThread t = new MyThread();
        t.start();
    }
}

--------------------------------------------------

2. RUNNABLE

- Runnable is an interface present in java.lang package.
- Contains only one method:

void run();

- A class implements Runnable and provides task logic.
- Thread object executes the Runnable task.

Example:

class MyTask implements Runnable {

    @Override
    public void run() {
        System.out.println("Task Running");
    }
}

public class Main {

    public static void main(String[] args) {

        Runnable r = new MyTask();

        Thread t = new Thread(r);

        t.start();
    }
}

--------------------------------------------------

3. INTERNAL WORKING

Using Thread:

MyThread t = new MyThread();

t.start();

JVM creates a new thread and internally calls:

t.run();

--------------------------------------------------

Using Runnable:

Runnable r = new MyTask();

Thread t = new Thread(r);

t.start();

Internally:

Thread executes:

r.run();

--------------------------------------------------

4. MAJOR DIFFERENCE

THREAD
------
- Defines both Thread and Task.
- Class must extend Thread.
- Cannot extend another class.

RUNNABLE
--------
- Defines only Task.
- Thread executes the task.
- Class can still extend another class.

Example:

class Employee extends Person
               implements Runnable

This is possible.

class Employee extends Person
               extends Thread

Not possible.

--------------------------------------------------

5. WHICH IS BETTER?

Runnable is preferred because:

1. Supports Multiple Inheritance

class Employee extends Person
               implements Runnable

2. Better Object-Oriented Design

Task and Thread are separated.

3. Recommended in Real Projects

Most frameworks use Runnable.

--------------------------------------------------

6. MEMORY VIEW

Using Thread:

MyThread
   |
   --> run()

Task and Thread are tightly coupled.

--------------------------------------------------

Using Runnable:

Runnable Task
      |
      V

Thread
      |
      V

run()

Task and Execution are separate.

--------------------------------------------------

=========================================
WHAT IS SYNCHRONIZATION IN JAVA?
=========================================

Definition:

Synchronization is a mechanism that allows only one thread to access a shared resource at a time.

It prevents data inconsistency and race conditions when multiple threads access the same resource simultaneously.

--------------------------------------------------

WHY DO WE NEED SYNCHRONIZATION?

Suppose two threads are accessing the same bank account.

Without Synchronization:

Balance = 1000

Thread-1 withdraws 500
Thread-2 withdraws 700

Both threads read:

Balance = 1000

Thread-1 updates:
Balance = 500

Thread-2 updates:
Balance = 300

Final Balance may become incorrect because both threads modified the shared resource concurrently.

This problem is called:

RACE CONDITION

--------------------------------------------------

WHAT IS A RACE CONDITION?

A race condition occurs when multiple threads access and modify shared data simultaneously, causing unexpected results.

Example:

class Counter {

    int count = 0;

    public void increment() {
        count++;
    }
}

Two threads execute:

count++;

Expected Output:

2000

Actual Output:

May be 1500, 1800, 1950, etc.

Reason:
count++ is not an atomic operation.

--------------------------------------------------

INTERNAL WORKING OF count++

count++;

Actually performs:

1. Read count
2. Increment count
3. Write count

Example:

count = 5

Thread-1 reads 5
Thread-2 reads 5

Thread-1 increments to 6
Thread-2 increments to 6

Final Value = 6

Expected Value = 7

This causes data inconsistency.

--------------------------------------------------

SOLUTION: SYNCHRONIZATION

class Counter {

    int count = 0;

    public synchronized void increment() {
        count++;
    }
}

Now only one thread can execute increment() at a time.

Result:

Correct Output = 2000

--------------------------------------------------

HOW SYNCHRONIZATION WORKS?

Every Java object has an intrinsic lock (monitor lock).

When a thread enters a synchronized block:

1. Thread acquires lock
2. Executes code
3. Releases lock

Other threads must wait until the lock is released.

--------------------------------------------------

EXAMPLE

class Test {

    synchronized void print() {

        for(int i=1;i<=5;i++) {
            System.out.println(i);
        }
    }
}

Thread-1 acquires lock

Thread-2 waits

After Thread-1 finishes:

Thread-2 acquires lock

--------------------------------------------------

2. Synchronized Block

3. Static Synchronization

=========================================

Both synchronized and ReentrantLock are used to achieve thread safety and prevent multiple threads from accessing shared resources simultaneously.

            lock.unlock();
        }
    }
}

        );
    }

    public static void main(
        String[] args) {

        t = null;

        System.out.println("End");
    }
}

Possible Output:

End
Finalize Called

OR

End

Reason:

JVM does not guarantee finalize() execution.

An object can make itself reachable again inside finalize().

    static Test obj;

    @Override

    }

This makes garbage collection complicated.

INTERVIEW ANSWER (1 MINUTE)

finalize() is a method defined in java.lang.Object that was originally intended to perform cleanup
 operations before an object is garbage collected. When an object becomes unreachable,
 the JVM may invoke finalize() before reclaiming its memory. However, there is no guarantee that
 finalize() will execute or when it will execute. Due to its unpredictable behavior, performance issues,

=========================================
HASHMAP vs CONCURRENTHASHMAP
=========================================

Both HashMap and ConcurrentHashMap store data as Key-Value pairs.

The main difference is:

HashMap is NOT thread-safe.
ConcurrentHashMap is thread-safe.

--------------------------------------------------

1. HASHMAP

Package:

java.util.HashMap

Features:

- Not synchronized
- Not thread-safe
- Faster in single-threaded applications
- Multiple threads can modify data simultaneously

Example:

HashMap<Integer,String> map =
new HashMap<>();

map.put(1,"Java");

--------------------------------------------------

2. CONCURRENTHASHMAP

Package:

java.util.concurrent.ConcurrentHashMap

Features:

- Thread-safe
- Supports concurrent read/write
- Used in multi-threaded applications
- Better performance than Hashtable

Example:

ConcurrentHashMap<Integer,String> map =
new ConcurrentHashMap<>();

map.put(1,"Java");

--------------------------------------------------

3. PROBLEM WITH HASHMAP

Suppose:

Thread-1:
map.put(1,"Java");

Thread-2:
map.put(2,"Spring");

Both threads modify the map simultaneously.

Result:

- Data inconsistency
- Race conditions
- Corrupted internal structure

HashMap is unsafe in multithreaded environments.

--------------------------------------------------

4. HOW HASHMAP WORKS?

HashMap uses:

- Array of Buckets
- Linked List
- Red Black Tree (Java 8)

No synchronization exists.

Multiple threads can access the same bucket simultaneously.

--------------------------------------------------

5. HOW CONCURRENTHASHMAP WORKS?

Java 7:

Segment-Based Locking

Map divided into multiple segments.

Only affected segment is locked.

--------------------------------------------------

Java 8:

Segment concept removed.

Uses:

- CAS (Compare And Swap)
- Synchronized at bucket level
- Fine-grained locking

Multiple threads can work on different buckets simultaneously.

--------------------------------------------------

6. NULL SUPPORT

HashMap:

Allows:

1 Null Key

Multiple Null Values

Example:

map.put(null,"Java");

map.put(1,null);

Valid.

--------------------------------------------------

ConcurrentHashMap:

Null Key NOT allowed

Null Value NOT allowed

Example:

map.put(null,"Java");

Throws:

NullPointerException

--------------------------------------------------

Reason:

ConcurrentHashMap cannot distinguish between:

map.get(key)

Returning:

null

because:

1. Key absent

OR

2. Value is null

To avoid ambiguity, nulls are prohibited.

--------------------------------------------------

7. SYNCHRONIZATION

HashMap:

No synchronization

--------------------------------------------------

ConcurrentHashMap:

Thread-safe synchronization

Uses:

Node level locking
CAS operations

--------------------------------------------------

8. FAIL-FAST vs FAIL-SAFE

HashMap Iterator:

Fail-Fast

Example:

for(Integer key : map.keySet()) {

    map.put(5,"Angular");
}

Throws:

ConcurrentModificationException

--------------------------------------------------

ConcurrentHashMap Iterator:

Fail-Safe

Example:

for(Integer key : map.keySet()) {

    map.put(5,"Angular");
}

No Exception

Iterator works on a snapshot of data.

--------------------------------------------------

9. PERFORMANCE

HashMap

Single Thread:

Faster

Because:

No locking overhead

--------------------------------------------------

ConcurrentHashMap

Multi Thread:

Faster

Because:

Supports concurrent access.

--------------------------------------------------

10. INTERNAL LOCKING

HashMap:

No Lock

Thread-1
   |
   V
 Map

Thread-2
   |
   V
 Map

Both modify data simultaneously.

--------------------------------------------------

ConcurrentHashMap:

Bucket Lock

Thread-1 -> Bucket-1

Thread-2 -> Bucket-5

Both can execute at same time.

Higher throughput.

--------------------------------------------------

11. EXAMPLE

HashMap

Map<Integer,String> map =
new HashMap<>();

Runnable task = () -> {

    for(int i=1;i<=1000;i++) {

        map.put(i,"Java");
    }
};

Can lead to inconsistent results.

--------------------------------------------------

ConcurrentHashMap

Map<Integer,String> map =
new ConcurrentHashMap<>();

Runnable task = () -> {

    for(int i=1;i<=1000;i++) {

        map.put(i,"Java");
    }
};

Safe for multithreading.

ConcurrentHashMap:

Multiple threads work simultaneously.

Higher performance.
