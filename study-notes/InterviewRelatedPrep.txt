What is Immutability?

An immutable object is an object whose state cannot be changed after it is created.

Once an immutable object is created:

✅ Values cannot be modified
 ✅ New values require creating a new object
 ✅ Thread-safe by nature
 ✅ Safe to share across multiple threads
 
String str = "Hello";
str.concat(" World");

System.out.println(str);
output:
Hello


Immutable Object
String str = "Hello";

str = str.concat(" World");

System.out.println(str);
output:
Hello World

creates a new object and the reference is updated.

Why is String Immutable?
Java designers made String immutable primarily for:

String Pool Optimization
Security
Thread Safety
HashMap Performance
Class Loading Safety

String s1 = "Java";
String s2 = "Java";

Java stores literals inside the String Pool.

                   String Pool
                +-----------+
s1 -----------> |  "Java"   |
                +-----------+
s2 -----------> |

Reason 1: String Constant Pool
If String Were Mutable

s1.toUpperCase();

s1 -> "JAVA"
s2 -> "JAVA"

Now s2 is unexpectedly changed.

This would break String Pooling completely.

Therefore String must be immutable.

Reason 2: Security

Java uses Strings extensively in:

Database URLs
File Paths
Network Connections
Usernames
Passwords


Reason 3: Thread Safety

String str = "Java";

Shared among multiple threads.

Thread-1
Thread-2
Thread-3

All threads safely access the same object.

No synchronization needed.




Reason 4: HashMap Performance

HashMap<String, Integer> map = new HashMap<>();

hashCode("India")

Problem if String Was Mutable

String country = "India";

map.put(country,100);

country = "USA";

String caches its hash code.

Comparable vs Comparator in Java
1. Comparable

Comparable is used when a class has a natural ordering.
public interface Comparable<T> {
    int compareTo(T o);
}


class Employee implements Comparable<Employee> {

    int id;
    String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public int compareTo(Employee e) {
        return this.id - e.id;
    }
}


List<Employee> list = new ArrayList<>();

list.add(new Employee(103,"John"));
list.add(new Employee(101,"David"));
list.add(new Employee(102,"Sam"));

Collections.sort(list);

Output:
101 David
102 Sam
103 John

How compareTo() Works

@Override
public int compareTo(Employee e) {
    return this.id - e.id;
}

Returns:

< 0  => current object is smaller
= 0  => both are equal
> 0  => current object is greater

100 - 200 = -100 (some assumption)
Current object comes before.


2. Comparator

Used when we need custom sorting.

public interface Comparator<T> {
    int compare(T o1, T o2);
}

Example: Sort Employee by Name

class NameComparator
        implements Comparator<Employee> {

    @Override
    public int compare(Employee e1,
                       Employee e2) {

        return e1.name.compareTo(e2.name);
    }
}

Collections.sort(list,
                 new NameComparator());
				 
Output:
David
John
Sam
