Lifecycle hooks are methods provided by Angular that allow you to
execute code at specific stages of a component's life, from creation to
destruction.

Data Binding in Angular is a mechanism that enables communication 
between the component class and the HTML template. It helps display data
in the UI and respond to user actions without manually manipulating the DOM.

d)ANGULAR TRACKBY NOTES


1. WHAT IS TRACKBY?
-------------------

trackBy is a function used with *ngFor to uniquely identify each item
in a list.

It helps Angular reuse existing DOM elements instead of recreating them.

This improves performance, especially for large lists.

Syntax:

<li *ngFor="let emp of employees; trackBy: trackById">
</li>

--------------------------------------------------

2. WHY DO WE NEED TRACKBY?
--------------------------

Without trackBy:
- Angular recreates all DOM elements when list changes.
- More rendering.
- Poor performance for large data.

With trackBy:
- Angular identifies items using unique id.
- Only changed items are updated.
- Existing DOM elements are reused.

--------------------------------------------------

3. EXAMPLE WITHOUT TRACKBY
--------------------------

employees = [
 {id:1,name:'John'},
 {id:2,name:'David'},
 {id:3,name:'Sam'}
];

HTML:

<li *ngFor="let emp of employees">
   {{emp.name}}
</li>

Suppose a new employee is added:

employees = [
 {id:4,name:'Tom'},
 {id:1,name:'John'},
 {id:2,name:'David'},
 {id:3,name:'Sam'}
];

Angular may recreate multiple DOM elements.

--------------------------------------------------

4. EXAMPLE WITH TRACKBY
-----------------------

HTML:

<li *ngFor="let emp of employees; trackBy: trackById">
   {{emp.name}}
</li>

Component:

trackById(index:number,item:any){
   return item.id;
}

When a new employee is added:

employees = [
 {id:4,name:'Tom'},
 {id:1,name:'John'},
 {id:2,name:'David'},
 {id:3,name:'Sam'}
];

Angular identifies:

1 -> Existing
2 -> Existing
3 -> Existing
4 -> New

Only new record is rendered.

--------------------------------------------------

5. HOW TRACKBY WORKS
--------------------

Angular compares:

Without trackBy:
--------------
Object References

Old List:
John
David
Sam

New List:
John
David
Sam

Even if data is same but object references change,
Angular may re-render.

With trackBy:
-------------
Angular compares unique IDs.

1
2
3

If IDs are same, Angular reuses DOM elements.

--------------------------------------------------

6. REAL-TIME EXAMPLE
--------------------

Employee Management System

API Response:

[
 {id:1,name:'John'},
 {id:2,name:'David'},
 {id:3,name:'Sam'}
]

Every refresh returns new object references.

Without trackBy:
Angular recreates all rows.

With trackBy:
Angular matches ids and updates only changed rows.

Performance improves significantly.

--------------------------------------------------

7. TRACKBY USING ID
-------------------

trackById(index:number,item:any){
   return item.id;
}

Most commonly used approach.

--------------------------------------------------

8. TRACKBY USING INDEX
----------------------

trackByIndex(index:number,item:any){
   return index;
}

HTML:

<li *ngFor="let emp of employees; trackBy: trackByIndex">
</li>

Note:
Using id is preferred over index.

ANGULAR SUBSCRIPTION MANAGEMENT

1. SUBSCRIPTION ARRAY

Used to store multiple subscriptions in an array and unsubscribe them together.

Example:

import { Subscription } from 'rxjs';

export class UserComponent implements OnInit, OnDestroy {

  subscriptions: Subscription[] = [];

  ngOnInit() {

    const sub1 = this.userService.getUsers()
      .subscribe(users => console.log(users));

    const sub2 = this.userService.getRoles()
      .subscribe(roles => console.log(roles));

    this.subscriptions.push(sub1, sub2);
  }

  ngOnDestroy() {
    this.subscriptions.forEach(sub => sub.unsubscribe());
  }
}

Advantages:
- Easy to understand
- No external library required

Disadvantages:
- More boilerplate code
- Easy to forget adding subscriptions to array


==================================================

2. SUBSINK

SubSink is a third-party library that manages multiple subscriptions.

Installation:

npm install subsink

Example:

import { SubSink } from 'subsink';

export class UserComponent implements OnInit, OnDestroy {

  private subs = new SubSink();

  ngOnInit() {

    this.subs.sink = this.userService.getUsers()
      .subscribe(users => console.log(users));

    this.subs.sink = this.userService.getRoles()
      .subscribe(roles => console.log(roles));
  }

  ngOnDestroy() {
    this.subs.unsubscribe();
  }
}

Alternative:

this.subs.add(
  this.userService.getUsers().subscribe(),
  this.userService.getRoles().subscribe(),
  this.userService.getDepartments().subscribe()
);

Advantages:
- Cleaner than subscription array
- Easy to manage multiple subscriptions

Disadvantages:
- Requires external dependency
- Less preferred after Angular 16


==================================================

3. TAKEUNTIL()

Most commonly used before Angular 16.

Example:

import { Subject } from 'rxjs';
import { takeUntil } from 'rxjs/operators';

export class UserComponent implements OnInit, OnDestroy {

  private destroy$ = new Subject<void>();

  ngOnInit() {

    this.userService.getUsers()
      .pipe(
        takeUntil(this.destroy$)
      )
      .subscribe(users => console.log(users));

    this.userService.getRoles()
      .pipe(
        takeUntil(this.destroy$)
      )
      .subscribe(roles => console.log(roles));
  }

  ngOnDestroy() {
    this.destroy$.next();
    this.destroy$.complete();
  }
}

Working:

Observable
    |
takeUntil(destroy$)
    |
subscribe()

destroy$.next()
    |
Auto Unsubscribe

Advantages:
- No need to keep subscription references
- Widely used in Angular projects

Disadvantages:
- Need Subject
- Need ngOnDestroy


==================================================

4. TAKEUNTILDESTROYED()

Recommended in Angular 16+

Example:

import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

export class UserComponent {

  ngOnInit() {

    this.userService.getUsers()
      .pipe(takeUntilDestroyed())
      .subscribe(users => console.log(users));

    this.userService.getRoles()
      .pipe(takeUntilDestroyed())
      .subscribe(roles => console.log(roles));
  }
}

Using DestroyRef:

import { DestroyRef, inject } from '@angular/core';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

export class UserComponent {

  private destroyRef = inject(DestroyRef);

  ngOnInit() {

    this.userService.getUsers()
      .pipe(
        takeUntilDestroyed(this.destroyRef)
      )
      .subscribe(data => console.log(data));
  }
}

Advantages:
- Angular built-in
- No Subject required
- No ngOnDestroy required
- Cleanest approach

Disadvantages:
- Available only in Angular 16+




==================================================

REAL-TIME EXAMPLE (FORM VALUE CHANGES)

Wrong:

this.form.get('name')?.valueChanges
  .subscribe(value => {
    console.log(value);
  });

If component reloads multiple times:

Subscription 1 -> Active
Subscription 2 -> Active
Subscription 3 -> Active

Memory Leak occurs.

Correct:

this.form.get('name')?.valueChanges
  .pipe(takeUntilDestroyed())
  .subscribe(value => {
    console.log(value);
  });

Angular automatically unsubscribes when component is destroyed.


5. ASYNC PIPE

The Async Pipe automatically subscribes and unsubscribes from Observables.
It is the best approach when data is used only in the HTML template.

Component:

import { Observable } from 'rxjs';

export class UserComponent {

  users$: Observable<User[]> =
    this.userService.getUsers();
}

Template:

<div *ngFor="let user of users$ | async">
  {{ user.name }}
</div>

Flow:

Observable
    |
 Async Pipe
    |
 Subscribe Automatically
    |
 Display Data
    |
 Component Destroyed
    |
 Unsubscribe Automatically

Advantages:
- No manual subscribe()
- No unsubscribe()
- No memory leaks
- Cleaner code
- Recommended for template data binding

Disadvantages:
- Cannot perform complex logic easily inside subscribe()
- Mainly useful when displaying data in UI

==================================================

ASYNC PIPE WITH HTTP CALL

Component:

users$ = this.http.get<User[]>('/api/users');

Template:

<ul>
  <li *ngFor="let user of users$ | async">
    {{ user.name }}
  </li>
</ul>

Angular automatically:
- Subscribes
- Receives data
- Updates UI
- Unsubscribes when component is destroyed

==================================================

ASYNC PIPE WITH LOADING STATE

Component:

users$ = this.userService.getUsers();

Template:

<ng-container *ngIf="users$ | async as users; else loading">

  <div *ngFor="let user of users">
    {{ user.name }}
  </div>

</ng-container>

<ng-template #loading>
  Loading...
</ng-template>

==================================================

WHEN TO USE WHICH?

1. Async Pipe
   - For template data binding
   - Best option

2. takeUntilDestroyed()
   - For subscriptions inside component TS file
   - Angular 16+

3. takeUntil()
   - Older Angular projects

4. SubSink
   - Multiple subscriptions in legacy projects

5. Subscription Array
   - Simple projects

Reactive Forms are a model-driven approach to handling forms in Angular.
Instead of writing most logic in HTML, we create and manage the form structure in the TypeScript component.

@NgModule({

    ReactiveFormsModule
  ]
})

``

Step 2: Create FormGroup

import { Component } from '@angular/core';
import { FormGroup, FormControl } from '@angular/forms';

@Component({
  selector: 'app-user-registration',
  templateUrl: './user-registration.component.html'
})
export class UserRegistrationComponent {

  registrationForm = new FormGroup({
    username: new FormControl(''),
    email: new FormControl(''),
    password: new FormControl('')
  });

  onSubmit() {
    console.log(this.registrationForm.value);
  }
}

TYPES OF COMPONENTS IN ANGULAR

Angular does not officially classify components into strict types, but in real-world projects we commonly categorize them as follows:

==================================================

1. ROOT COMPONENT (APP COMPONENT)

This is the first component loaded when the application starts.

Example:

app.component.ts

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
}

app.component.html

<h1>Welcome to Angular</h1>
<app-header></app-header>

Role:
- Parent of all components
- Entry point of Angular application

==================================================

2. PRESENTATIONAL (DUMB) COMPONENT

Used only for displaying data.
Does not contain business logic.

Example:

@Component({
  selector: 'app-user-list',
  template: `
    <div *ngFor="let user of users">
      {{user.name}}
    </div>
  `
})
export class UserListComponent {

  @Input()
  users: any[] = [];
}

Responsibilities:
- UI Rendering
- Input data display
- Emit events to parent

Advantages:
- Reusable
- Easy to test

==================================================

3. CONTAINER (SMART) COMPONENT

Responsible for fetching data and handling business logic.

Example:

@Component({
  selector: 'app-user-container',
  template: `
    <app-user-list
      [users]="users">
    </app-user-list>
  `
})
export class UserContainerComponent {

  users: any[] = [];

  ngOnInit() {
    this.userService.getUsers()
      .subscribe(data => {
        this.users = data;
      });
  }
}

Responsibilities:
- API Calls
- Business Logic
- State Management

==================================================

4. SHARED COMPONENT

Reusable across multiple modules.

Examples:
- Header Component
- Footer Component
- Loader Component
- Button Component

Example:

<app-loader></app-loader>

<app-header></app-header>

<app-footer></app-footer>

Purpose:
- Reusability
- Avoid code duplication

==================================================

5. FEATURE COMPONENT

Belongs to a specific feature/module.

Examples:

User Module
 ├── UserListComponent
 ├── UserAddComponent
 └── UserEditComponent

Product Module
 ├── ProductListComponent
 ├── ProductDetailsComponent
 └── ProductEditComponent

Purpose:
- Implement business-specific functionality

==================================================

6. LAYOUT COMPONENT

Used to define page structure.

Example:

@Component({
 selector: 'app-layout',
 template: `
  <app-header></app-header>

  <router-outlet></router-outlet>

  <app-footer></app-footer>
 `
})
export class LayoutComponent {}

Purpose:
- Common page layout
- Navigation structure

==================================================

7. DYNAMIC COMPONENT

Created dynamically at runtime.

Example:

constructor(
  private viewContainerRef: ViewContainerRef
) {}

loadComponent() {

  this.viewContainerRef.createComponent(
    UserComponent
  );

}

Use Cases:
- Popups
- Dialogs
- Dynamic Forms

==================================================

8. STANDALONE COMPONENT (Angular 14+)

Does not require NgModule.

Example:

@Component({
  selector: 'app-user',
  standalone: true,
  imports: [CommonModule],
  template: `<h2>User Component</h2>`
})
export class UserComponent {
}

Bootstrap:

bootstrapApplication(AppComponent);

Advantages:
- Less boilerplate
- Better tree shaking
- Modern Angular approach

==================================================

9. ROUTED COMPONENT

Loaded via Angular Router.

Routes:

const routes = [
 {
   path: 'users',
   component: UserComponent
 }
];

UserComponent becomes a routed component.

Access URL:

http://localhost:4200/users
