Angular LifeCycle hooks:

Lifecycle hooks are methods provided by Angular that allow you to
execute code at specific stages of a component's life, from creation to
destruction.

Component Phases:

1. Creation
2. Input Property Changes
3. Rendering/View Initialization
4. Change Detection
5. Destruction

1. Constructor
used for dependecy injection.
variable Initialization.
Do not call APIs in constructor.
Use ngOnInit() for API calls.

2. ngOnChanges()
Called whenever an @Input() property changes.

Parent Component:
<app-child [username]="name"></app-child>
Child Component:

import { Component, Input, OnChanges, SimpleChanges } from '@angular/core';
 
export class ChildComponent implements OnChanges {
 
@Input() username!: string;
 
ngOnChanges(changes: SimpleChanges) {
console.log(changes);
}
}

Use Cases
React when parent sends new data
Refresh component state
Perform validation

3. ngOnInit()
Called only once after component initialization.

export class UserComponent implements OnInit {

  ngOnInit() {
    console.log("Component Initialized");
  }
}

Common Uses

✅ API Calls

✅ Load Data

✅ Initialize Form

✅ Retrieve Route Parameters

ngOnInit() {
this.userService.getUsers().subscribe(data => {
this.users = data;
});
}

4. ngDoCheck()
Called during every Angular change detection cycle.

ngDoCheck() {
   console.log("Change Detection Running");
}

Whenever:

Button Click
Input Change
HTTP Response
Timer Event

This hook gets executed.

5. ngAfterContentInit()
Called once after content projection (ng-content) is initialized.

Parent:

<app-card>
   <h2>Hello Angular</h2>
</app-card>

Child:

<div class="card">
   <ng-content></ng-content>
</div>

ngAfterContentInit() {
console.log("Content Initialized");
}

6. ngAfterContentChecked()
Called after projected content is checked.

ngAfterContentChecked() {
console.log("Content Checked");
}

Use Case

Validate projected content changes.

7. ngAfterViewInit()

Called once after component view and child views are initialized.

<input #userInput>

@ViewChild('userInput')
inputElement!: ElementRef;
 
ngAfterViewInit() {
this.inputElement.nativeElement.focus();
}

Use Cases

✅ Access DOM Elements

✅ Access Child Components

✅ Initialize Charts

✅ Initialize Third-party Libraries

@ViewChild(ChartComponent)
chart!: ChartComponent;

ngAfterViewInit() {
   this.chart.loadData();
}

8. ngAfterViewChecked()
Called after Angular checks component views.

ngAfterViewChecked() {
   console.log("View Checked");
}

Use Case

Rarely used for:

Monitoring view updates
Debugging

9. ngOnDestroy()

Called just before component is destroyed.

Very important hook.

ngOnDestroy() {
   console.log("Component Destroyed");
}

subscription!: Subscription;

  this.subscription =
      this.userService.getUsers()
      .subscribe();
}

ngOnDestroy() {
  this.subscription.unsubscribe();
}

What is Data Binding in Angular?
Data Binding in Angular is a mechanism that enables communication 
between the component class and the HTML template. It helps display data
in the UI and respond to user actions without manually manipulating the DOM.

Types

1. Interpolation
Used to display component data in HTML.
{{ expression }}
<p>{{ name.toUpperCase() }}</p>
<p>{{ isActive }}</p>

2. Property Binding
Used to bind component data to HTML element properties.
[property]="value"

Component:
imageUrl = "assets/user.png";

template:
<img [src]="imageUrl">

component:
isDisbled = true;

template:
<button [disabled]="isDisabled">
   Submit
</button>

component:
color = 'red';

template:
<p [style.color]="color">
   Welcome
</p>

3. Event Binding
Used to handle user events.
(event)="method()"

component:
showMessage() {
alert("Button Clicked");
}

template:
<button (click)="showMessage()">
   Click Me
</button>

component:
onType(event:any) {
   console.log(event.
   
template:
<input (input)="onType($event)">   

4. Two-Way Binding
Property Binding
+
Event Binding

component:

template:

<p>{{name}}</p>

Reactive Forms
Reactive Forms are a model-driven approach to handling forms in Angular.
Instead of writing most logic in HTML, we create and manage the form structure in the TypeScript component.

Step 1: Import ReactiveFormsModule

import { ReactiveFormsModule } from '@angular/forms';

@NgModule({
  imports: [
    ReactiveFormsModule
  ]
})
export class AppModule {}
``

Step 2: Create FormGroup

import { Component } from '@angular/core';
import { FormGroup, FormControl } from '@angular/forms';

@Component({
  selector: 'app-user-registration',
  templateUrl: './user-registration.component.html'
})
export class UserRegistrationComponent {

  registrationForm = new FormGroup({
    username: new FormControl(''),
    email: new FormControl(''),
    password: new FormControl('')
  });

  onSubmit() {
    console.log(this.registrationForm.value);
  }
}

Step 3: HTML Binding

<form [formGroup]="registrationForm" (ngSubmit)="onSubmit()">

  <label>Username</label>
  <input type="text" formControlName="username">

  <br><br>

  <label>Email</label>
  <input type="email" formControlName="email">

  <br><br>

  <label>Password</label>
  <input type="password" formControlName="password">

  <br><br>

  <button type="submit">Submit</button>

</form>

Important Terminologies

1. FormControl
Represents a single input field.
username = new FormControl('');
email = new FormControl('');
password = new FormControl('');

2. FormGroup
Group of multiple controls.
registrationForm = new FormGroup({
username: new FormControl(''),
email: new FormControl('')
});

3. FormBuilder
Reduces boilerplate code

import { FormBuilder } from '@angular/forms';

constructor(private fb: FormBuilder) {}

form = this.fb.group({
  username: [''],
  email: [''],
  password: ['']
});
