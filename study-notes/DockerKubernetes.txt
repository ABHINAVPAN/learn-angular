DAY 1 - DOCKER BASICS
==========================

1. WHAT IS DOCKER?
------------------
- Docker is an open-source containerization platform.
- Used to package applications along with dependencies.
- Ensures applications run consistently across environments.
- Lightweight and faster than Virtual Machines.

Formula:
Application + Dependencies + Configuration = Container

Benefits:
- Consistent deployment
- Easy scalability
- Fast startup
- Better resource utilization
- CI/CD support

Example:
Spring Boot App + Java + Required Libraries
=> Packaged into a Docker Container

=================================================

2. IMAGE VS CONTAINER
----------------------

Docker Image:
- Read-only template
- Blueprint for containers
- Used to create containers

Docker Container:
- Running instance of an image
- Executes the application
- Has its own process

Java Analogy:

Image = Class

class Car {
}

Container = Object

Car c1 = new Car();
Car c2 = new Car();

Difference:

Image
- Blueprint
- Static
- Read-only

Container
- Running Application
- Dynamic
- Read/Write Layer

Commands:

Download Image:
docker pull nginx

List Images:
docker images

Create Container:
docker run nginx

Running Containers:
docker ps

All Containers:
docker ps -a

4. DOCKER ARCHITECTURE
-----------------------

Main Components:

1. Docker Client
   - Accepts user commands
   - Communicates with Docker Daemon

2. Docker Daemon (dockerd)
   - Core Docker Engine
   - Builds images
   - Runs containers
   - Manages networks and volumes

3. Docker Registry
   - Stores Docker Images
   - Default Registry = Docker Hub

4. Images
   - Templates used to create containers

5. Containers
   - Running instances of images

Architecture Flow:

Docker Client
      |
      v
Docker Daemon
      |
 --------------------
 |        |         |
 v        v         v
Images Containers Networks

DAY 3 - DOCKERFILE & CUSTOM IMAGES
=========================

1. WHAT IS A DOCKERFILE?
------------------------

A Dockerfile is a text file that contains instructions
to build a Docker Image automatically.

It defines:
- Base Image
- Application Files
- Commands to Execute
- Ports to Expose
- Startup Command

Flow:

Dockerfile
     ↓
docker build
     ↓
Docker Image
     ↓
docker run
     ↓
Container

----------------------------------------------------------

2. COMMON DOCKERFILE INSTRUCTIONS
---------------------------------

FROM
- Specifies the base image.

Example:
FROM openjdk:17

----------------------------------------------------------

WORKDIR
- Sets the working directory inside container.

Example:
WORKDIR /app

----------------------------------------------------------

COPY
- Copies files from local machine to container.

Example:
COPY target/app.jar app.jar

----------------------------------------------------------

RUN
- Executes command during image build.

Example:
RUN apt-get update

----------------------------------------------------------

EXPOSE
- Documents which port application uses.

Example:
EXPOSE 8080

----------------------------------------------------------

CMD
- Default command executed when container starts.

Example:
CMD ["java","-jar","app.jar"]

----------------------------------------------------------

3. SIMPLE JAVA SPRING BOOT DOCKERFILE
-------------------------------------

Dockerfile

FROM openjdk:17

WORKDIR /app

COPY target/demo.jar demo.jar

EXPOSE 8080

CMD ["java","-jar","demo.jar"]

----------------------------------------------------------

Explanation:

FROM openjdk:17
-> Uses OpenJDK 17 as base image.

WORKDIR /app
-> Creates and switches to /app directory.

COPY target/demo.jar demo.jar
-> Copies application jar into container.

EXPOSE 8080
-> Application runs on port 8080.

CMD ["java","-jar","demo.jar"]
-> Starts Spring Boot application.

1. DOCKER VOLUMES
=================

WHAT IS A VOLUME?
-----------------

A Docker Volume is used to store data outside the container.

Why?
- Container data is lost when container is removed.
- Volumes provide persistent storage.
- Data remains even after container restart/removal.

Example:
MySQL Container
      ↓
Docker Volume
      ↓
Database Data Stored Permanently

----------------------------------------------------------

WITHOUT VOLUME
==============

Container Removed
        ↓
Data Lost

Example:

docker run --name mysql-container mysql

Remove Container:

docker rm -f mysql-container

Result:
Database data is lost.

----------------------------------------------------------

WITH VOLUME
===========

Container Removed
        ↓
Volume Remains
        ↓
Data Preserved

----------------------------------------------------------

CREATE VOLUME
=============

Create Volume:

docker volume create mysql-data

Verify Volumes:

docker volume ls

Inspect Volume:

docker volume inspect mysql-data

----------------------------------------------------------

USE VOLUME WITH CONTAINER
=========================

Syntax:

docker run -v volume-name:container-path image

Example:

docker run -d \
--name mysql-container \
-v mysql-data:/var/lib/mysql \
-e MYSQL_ROOT_PASSWORD=root \
mysql:8

Explanation:

-v mysql-data:/var/lib/mysql

mysql-data
-> Volume Name

/var/lib/mysql
-> MySQL data directory

----------------------------------------------------------

CHECK VOLUMES
=============

List Volumes:

docker volume ls

Inspect Volume:

docker volume inspect mysql-data

----------------------------------------------------------

REMOVE VOLUME
=============

docker volume rm mysql-data

Remove Unused Volumes:

docker volume prune

DAY 6 - DOCKER COMPOSE
=========================

WHAT IS DOCKER COMPOSE?
=======================

Docker Compose is a tool used to define and run
multiple containers using a single YAML file.

Instead of running multiple docker run commands,
Docker Compose can start all containers together.

Example:

Spring Boot Container
          +
MySQL Container
          +
Redis Container

Using:

docker-compose.yml

----------------------------------------------------------

WHY DOCKER COMPOSE?
===================

Without Docker Compose:

docker network create app-network

docker run mysql ...

docker run redis ...

docker run springboot-app ...

Multiple commands required.

----------------------------------------------------------

With Docker Compose:

docker compose up

Everything starts automatically.

----------------------------------------------------------

BENEFITS
========

1. Easy Multi-Container Management
2. Single Configuration File
3. Automatic Networking
4. Easy Scaling
5. Faster Local Development

----------------------------------------------------------

DOCKER COMPOSE FILE
===================

File Name:

docker-compose.yml

Basic Structure:

version: '3.8'

services:
  service-name:
    image: image-name

----------------------------------------------------------

SIMPLE NGINX EXAMPLE
====================

docker-compose.yml

version: '3.8'

services:

  nginx:
    image: nginx
    ports:
      - "8080:80"

Start:

docker compose up

Stop:

docker compose down

----------------------------------------------------------

SPRING BOOT + MYSQL EXAMPLE
===========================

docker-compose.yml

version: '3.8'

services:

  mysql:

    image: mysql:8

    container_name: mysql-container

    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: testdb

    ports:
      - "3306:3306"

  springboot-app:

    image: springboot-app

    container_name: springboot-container

    ports:
      - "8080:8080"

    depends_on:
      - mysql

----------------------------------------------------------

EXPLANATION
===========

services
---------
Defines all containers.

mysql
-----
Creates MySQL container.

springboot-app
--------------
Creates Spring Boot container.

environment
-----------
Sets environment variables.

----------

3. DEPLOY APPLICATION ON AWS EKS

WHAT IS EKS?
============

EKS = Elastic Kubernetes Service

Managed Kubernetes Service provided by AWS.

Used for:

- Container Orchestration
- Auto Scaling
- High Availability
- Production Deployments

----------------------------------------------------------

EKS ARCHITECTURE
================

Spring Boot Image
          ↓
        ECR
          ↓
    Kubernetes Deployment
          ↓
          EKS
          ↓
      Load Balancer
          ↓
        Users

----------------------------------------------------------

STEP 1: CREATE EKS CLUSTER
==========================

Using AWS Console

EKS
 ↓
Create Cluster

Cluster Name:

springboot-cluster

----------------------------------------------------------

STEP 2: CONNECT KUBECTL
=======================

aws eks update-kubeconfig \
--region ap-south-1 \
--name springboot-cluster

Verify:

kubectl get nodes

----------------------------------------------------------

STEP 3: CREATE DEPLOYMENT YAML
==============================

deployment.yaml

apiVersion: apps/v1

kind: Deployment

metadata:
  name: springboot-app

spec:
  replicas: 2

  selector:
    matchLabels:
      app: springboot-app

  template:

    metadata:
      labels:
        app: springboot-app

    spec:

      containers:

      - name: springboot-app

        image:
          123456789012.dkr.ecr.ap-south-1.amazonaws.com/springboot-app:latest

        ports:
        - containerPort: 8080

----------------------------------------------------------

DEPLOY APPLICATION
==================

kubectl apply -f deployment.yaml

Verify:

kubectl get deployments

kubectl get pods

----------------------------------------------------------

STEP 4: CREATE SERVICE
======================

service.yaml

apiVersion: v1

kind: Service

metadata:
  name: springboot-service

spec:

  selector:
    app: springboot-app

  ports:

  - protocol: TCP

    port: 80

    targetPort: 8080

  type: LoadBalancer

----------------------------------------------------------

DEPLOY SERVICE
==============

kubectl apply -f service.yaml

----------------------------------------------------------

VERIFY SERVICE
==============

kubectl get svc

Output:

EXTERNAL-IP

a1b2c3d4.ap-south-1.elb.amazonaws.com

ACCESS APPLICATION

http://EXTERNAL-IP
